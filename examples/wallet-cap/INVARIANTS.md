## wallet-cap

> "A wallet must never spend more than its cap."

**Approval:** all 3 contract files and forge.json match their approved hashes.

### Guarantees (from `spec/WalletSpec.dfy`)

- **W1** the total spent never goes over the cap.
- **W2** the cap never changes.
- **W3** a positive amount that fits is accepted and added exactly.
- **W4** every other amount is rejected with no change.

<details><summary>The approved spec, in full</summary>

```dafny
// Wallet with a spending cap, in whole cents.
abstract module WalletSpec {
  datatype Outcome = Ok | Rejected
  datatype State = Wallet(cap: int, spent: int)

  predicate Valid(s: State) { 0 <= s.spent <= s.cap }

  method Spend(s: State, amount: int) returns (next: State, outcome: Outcome)
    requires Valid(s)
    // W1: the total spent never goes over the cap.
    ensures Valid(next)
    // W2: the cap never changes.
    ensures next.cap == s.cap
    // W3: a positive amount that fits is accepted and added exactly.
    ensures (0 < amount && s.spent + amount <= s.cap) ==>
      outcome == Ok && next.spent == s.spent + amount
    // W4: every other amount is rejected with no change.
    ensures !(0 < amount && s.spent + amount <= s.cap) ==>
      outcome == Rejected && next == s
}
```

</details>

### Decisions (each one is checked by Dafny against the spec in `spec/WalletExamples.dfy`)

| Id | Question (concrete) | Answer |
| --- | --- | --- |
| D1 | Cap $50.00, spent $20.00, spend $30.00: allow reaching exactly the cap? | Allow |
| D2 | Cap $50.00, spent $40.00, spend $20.00: reject, or cut to $10.00? | Reject; never a partial spend |
| D3 | Spend $0.00: reject, or accept as a no-op? | Reject |
| D4 | Spend -$10.00: reject, or treat as a refund? | Reject; refunds are a separate rule |

### Defaults confirmed

- Money is whole cents (integers), no floats.
- Invalid input is rejected and changes nothing.

### Not guaranteed by this rule

- Who may spend (authorization).
- Several wallets sharing one cap; concurrency; persistence.

## Trust base (what every rule above rests on)

- The Dafny 4.11 verifier and the Z3 solver: a bug there could accept a false proof.
- The spec saying what the owner meant: the decisions above are checked against it; nothing checks the
  spec against intent beyond them.
- Dafny's compilers, for any compiled code (NATIVE CHECK), and the thin unproved wrappers around it.
- The application calling the proved code: `usedBy` is a text check, not a call-graph analysis.
- Fuzzing is a FINITE TEST: it finds differences; it does not prove their absence.
